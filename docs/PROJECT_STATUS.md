## 二、目前前端功能

### 1. 縣市與行政區兩層篩選

操作流程：

```text
縣市
↓
行政區
↓
CCTV 來源
```

目前支援：
- 縣市篩選
- 行政區篩選
- CCTV 類型／來源篩選
- 側邊欄清單與地圖 Marker 同步
- 點擊側邊欄項目可定位 Marker
- 點擊 Marker 可顯示站名、ID、來源、行政區與影像按鈕

### 2. 資料來源選單

已加入：
- 道路 CCTV
- 省道 CCTV
- 國道 CCTV
- 水情 CCTV
- 水情租賃 CCTV
- 水利署 CCTV

### 3. 數量統計

上方統計區已可顯示各來源 CCTV 數量。

水利署統計欄位已加入：

```js
wra: wraCams.length
```

### 4. 水利署影像功能

已完成：
- 依 `SourceId` 與 `ID` 呼叫 Cameras API
- 從 API 回傳資料中遞迴搜尋影像網址
- 取得最後一筆可用影像網址
- 開啟最新 JPG 靜態影像
- 按鈕載入中狀態
- 失敗提示與 Console 除錯資訊

目前按鈕建議文字：

```text
開啟最新影像
```

不建議稱為「即時串流」，因為目前公開資料是 JPG 快照。

## 三、水利署資料整合狀態

### 站點 API

本地檔案：

```text
./wra-stations.json
```

資料格式包含：

```json
{
  "SourceId": 1,
  "ID": "1",
  "Town_name": "新北市汐止區",
  "Name": "江長抽水站",
  "Counname": "新北市",
  "Basin_name": "淡水河",
  "lat": 25.0775,
  "lng": 121.6633
}
```

### Cameras API

格式：

```text
https://fhyv.wra.gov.tw/FhyWeb/v1/Api/CCTV/WRA/Cameras/{SourceId}/{ID}
```

測試結果：
- 前端 `fetch()` 成功
- 沒有遇到 CORS 阻擋
- 可取得靜態 JPG
- 不需要建立 Proxy

### 來源清理

水利署站點資料中混有其他單位影像，例如：
- 公路局／公路總局
- 台電
- 台水
- 有線電視
- 南科管理局
- 其他旁收來源

規劃在 `normalizeWraStations()` 中依下列條件排除：
- 非主要 `SourceId`
- 名稱含 `公路局`
- 名稱含 `公路總局`
- 名稱含 `旁收`
- 名稱含 `台電`
- 名稱含 `台水`
- 名稱含 `有線電視`
- 名稱含 `南科管理局`

此清理尚需再實際驗證，避免誤刪真正需要的水利署站點。

## 四、目前效能狀況

### 已發現問題

水利署約 2,521 筆，加上其他道路 CCTV 後，首頁會同時處理：
- 多個 JSON
- 數千筆正規化資料
- 數千個 Leaflet Marker
- 大量側邊欄項目
- 篩選選項重建

因此開啟網頁速度變慢。

### 目前採用的簡化方向

暫時不加入 Marker Cluster，因為修改範圍較大。

規劃改為：
- `allCams` 預設不包含 `wraCams`
- 選擇「水利署 CCTV」時才改用 `wraCams`
- 「全部 CCTV」預設不建立 2,521 個水利署 Marker

目前 `filteredCams()` 的核心邏輯應為：

```js
const sourceCams =
  source === "wra"
    ? wraCams
    : allCams;
```

同時 `allCams` 中移除：

```js
...wraCams,
```

注意：
- 水利署 JSON 仍會在首頁載入與解析
- 但預設不會建立全部水利署 Marker
- 效能應有改善，但尚未完成完整測試

## 五、縣市判定問題

### 問題描述

部分省道、國道 CCTV 沒有 `city` 欄位。

若只使用：

```js
normalizeCity(cam.city)
```

可能造成：
- 縣市空白
- 選特定縣市時無法納入
- 或因錯誤推測而被納入不正確縣市

### 已討論方案

#### 方案 A：文字判定

從以下欄位搜尋縣市名稱：
- `cam.name`
- `cam.rawName`
- `cam.district`
- `cam.source`
- `cam.location`

限制：
- 若只有道路編號與里程，例如 `T9D-063K+840`，文字中沒有縣市，無法可靠判定

#### 方案 B：道路編號＋里程對照表

例如：

```text
T9D-063K+840
→ 台9丁線 63K+840
→ 花蓮縣秀林鄉
```

限制：
- 全臺道路里程對照表會很長
- 後續維護成本高
- 道路改線或里程調整後需更新

#### 方案 C：經緯度＋行政區邊界判定

使用 CCTV 的 `lat`、`lng` 搭配縣市 GeoJSON。

優點：
- 最準確
- 不需手寫大量道路里程規則

限制：
- 前端計算較複雜
- 若每次篩選都重新判定，可能拖慢效能

### 建議方向

較適合的做法是：
1. 離線使用經緯度判定縣市與行政區
2. 將結果直接寫回省道與國道 JSON
3. 前端只讀取補好的 `city`、`district`
4. 避免在瀏覽器即時計算行政區邊界

目前尚未實作。
